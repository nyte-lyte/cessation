---
name: Read and discuss before making changes
description: User wants to read files and talk through the approach before any code changes
type: feedback
---

Always read the relevant file(s) first, then discuss what you found and what you're thinking. Do not jump to code edits without talking through the plan first.

**Why:** User has been burned by changes that felt too fast and went in the wrong direction. Discussing first lets them redirect before code is written.

**How to apply:** For any visual or logic change: (1) read, (2) describe what you see and what the change would do, (3) wait for confirmation before editing.

**Critical:** When the user shares external feedback for discussion, do NOT implement it. Treat shared feedback as a prompt to discuss pros/cons and get explicit go-ahead before touching any code. The user has corrected this multiple times.
